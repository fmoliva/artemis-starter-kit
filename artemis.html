The 3-step pipeline

From docs to green tests in three commands

Every feature follows the same repeatable sequence. No manual selector hunting, no login() in every test, no stale boilerplate.

Step 1
/context
Generate test cases
Claude reads your vault documentation and generates a structured TC file plus a Playwright spec — no browser needed.
Step 2
/explore
Harvest live selectors
Claude opens a browser, maps every input, button, and dropdown, and updates the selector catalog with confirmed IDs.
Step 3
/verify
Run, fix, record
Claude runs the spec via Playwright CLI, auto-fixes broken selectors, and records the Last Green date in the pipeline tracker.

Command reference

18 commands, every phase covered

Commands are slash-prefixed and run inside Claude Code. Each loads only the context it needs — no full skill reload on every run.

Onboarding & Config
/setup
Re-runs the onboarding wizard. Detects state, walks through questions, scaffolds project + vault.
Wizard
/sync
Pulls updates from GitHub for both the project repo and vault repo. Reports files changed, stops on conflicts.
CLI
/init
Initializes a new Artemis project from scratch. Creates folder structure, DB, and package.json.
CLI
Build Coverage
/context [feature]
Reads vault documentation → detects TC gaps → generates a TC file and Playwright spec. Zero browser.
No Browser
/explore [url]
Opens a browser, maps all inputs, buttons, dropdowns, and confirms selectors in the catalog.
Browser
/catalog [module]
Builds or updates the selector catalog from explore output using an 8-level selector hierarchy.
CLI
/ingest [file?]
Classifies raw/ content and routes each section to the correct vault location: bugs, feature docs, TCs, or selectors.
Multi-router
/parse [file]
Converts any document (DOCX, prose, checklist, table) into structured Artemis test cases.
Agent
Run & Verify
/verify [feature]
Runs the Playwright spec, auto-fixes broken selectors (up to 3 iterations), and records Last Green in the pipeline.
CLI + Auto-fix
/run [TC-ID] [url]
Executes a specific test case or scope via the Playwright CLI. Supports TC IDs or module names.
CLI
/resume
Continues a test run from the last checkpoint. Picks up remaining TCs, respects KNOWN_BLOCKS.
CLI
/artemis [url]
Full autonomous pipeline: explore → parse → generate → run. End-to-end coverage in one command.
Full Pipeline
Analyze & Debug
/bug [description]
Deep failure analysis: reproduces, classifies the failure layer (UI/API/Data/State/Timing), and writes a structured bug report.
Agent
/improve [spec-file]
Reviews and scores a test suite on 5 axes: Coverage, Selectors, Independence, Assertions, Maintainability.
Agent
/scope [description]
Recommends regression scope for a feature change. Scores every TC by relevance, outputs top 30 ranked.
Agent
/audit
4-pass health check: project folder, vault freshness, memory files, token budget. Writes a report to results/audits/.
Agent
/document [feature]
Generates a BA/SA developer reference document (.md + .docx) from vault feature files and explore screenshots. No browser needed.
Agent
/matrix
Builds a Feature × Test-Type coverage grid. Flags HIGH/MEDIUM/LOW gaps across all modules.
CLI
/diff [source] [target]
Compares TC libraries between two projects. Surfaces what one project covers that another doesn't.
CLI

The Second Brain Vault

Documentation that feeds test generation

The vault is a folder of Markdown files that describes your app. Artemis reads it to generate test cases without browser access — no live app required.

your-vault/
  _app-overview.md  ← loaded every session
  _test-data.md  ← loaded every session
  _pipeline.md  ← TC / Explored / Last Green
  known-bugs.md  ← open bugs affecting tests
  modules/
    [module]/
      [module].md  ← feature list
      [feature].md  ← loaded by /context
  cross-module/
    [shared-feature].md

    [module].md  ← confirmed by /explore
  raw/  ← dump zone → /ingest
    _archive/  ← processed files

Why Artemis

Stop writing boilerplate. Start shipping coverage.

Artemis is built around one idea: your documentation is already test cases — you just haven't told a computer about it yet.

📚
Vault-driven generation
Write feature docs once. /context converts them into TCs and Playwright specs automatically — no LLM hallucination, grounded in your documentation.
🔧
Self-healing selectors
/verify auto-fixes broken selectors up to 3 iterations. When your app changes, your tests adapt — not break.
👥
Built for teams
Skill and agents live in .claude/ and travel with the repo. A session-start sync check reminds everyone to pull before testing.
💰
Token-efficient by design
Lazy-loading references, phase-separated sessions, and startup limit params keep each session focused. No full context reload on every command.
🧪
Living test library
Test cases live in Markdown with structured IDs. /scope recommends regression targets. /matrix shows coverage gaps across all modules.
🤖
Human-in-the-loop gates
Every write action — TCs, bug reports, ingestion routing, learnings — shows a gate before committing. You stay in control while Claude does the heavy lifting.
📦
Raw ingestion pipeline
Dump session notes, bug observations, and requirements into raw/. /ingest classifies and routes each section to the right vault location.
🔍
Deep failure analysis
/bug reproduces the failure, classifies the layer (UI/API/Data/State/Timing), and writes a structured report with network evidence and root cause hypothesis.

Installation

Get started in minutes

Download the Starter Kit, open it in Claude Code, and the wizard handles everything else. No commands to memorize, no config files to write.

Easiest — Solo or small team

Download ZIP

Download the Starter Kit, unzip it anywhere, and open the folder in Claude Code.

  • 1
    Download artemis-starter-kit.zip from GitHub releases and unzip it
  • 2
    Open the unzipped folder in Claude Code (File → Open Folder)
  • 3
    Claude detects a fresh install and starts Wizard A automatically
  • 4
    Answer 4 questions, fill in .env, say “ready” — done
Best for Teams

Clone from GitHub

Clone the Starter Kit as your project repo. Push to your own org — teammates clone and Claude walks them through joining.

  • 1
    Clone (or fork) the Starter Kit: git clone https://github.com/yourorg/artemis-starter-kit.git my-app-tests cd my-app-tests
  • 2
    Open in Claude Code — Wizard A runs automatically
  • 3
    After setup, push your project repo to GitHub (without .env)
  • 4
    Teammates clone and open — Claude detects .artemis-project (State B) and runs Wizard B: vault clone + their own credentials

What gets committed vs. what stays private

PathCommit?Why
.artemis-project ✓ Yes App name + vault path — defines the project for every teammate
.claude/ (skill + agents) ✓ Yes Artemis itself — commands, subagents, reference docs
tests/ & test-cases/ ✓ Yes Playwright specs and TC library — shared test coverage
vault/ ✓ Separate repo Gitignored in the project repo; lives in its own repo cloned to ./vault/
.env ✗ Never Contains credentials — each person creates their own (gitignored)
playwright/.auth/ ✗ Never Saved login session — machine-specific and credential-bound
